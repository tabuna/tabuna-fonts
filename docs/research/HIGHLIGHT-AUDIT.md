# Highlight audit

Запуск полного сравнения системного и TabunaSans шрифта:

```sh
./scripts/run-highlight-audit.sh --sizes 32,64,128
```

Для пилота одного или нескольких glyphs:

```sh
./scripts/run-highlight-audit.sh --chars 'Дф' --sizes 64
```

Результат сохраняется в `build/highlight-audit/report.json`. Для каждого glyph
создаётся PNG с красным FN, синим FP и серым совпадением. JSON также содержит
IoU, площади FP/FN, BBox обеих масок, разницу BBox, крупнейшие связные области
и оценку толщины штриха через distance transform.

Для полностью автоматического запуска анализа ошибок после рендера:

```sh
./scripts/run-highlight-audit.sh --sizes 32,64,128 --analyze
```

Дополнительно создаются `highlight-analysis.json` и `highlight-atlas.png` в
каталоге каждого размера. Анализ ранжирует glyphs по связным FN/FP областям и
помечает вероятную причину (`смещение`, `масштаб/bbox`, `штрих тонкий/толстый`,
`пропуск контура`, `лишний контур`, `сглаживание`).

Для перехода от перебора параметров к реконструкции геометрии запусти после
аудита:

```sh
./.venv/bin/python scripts/geometry-audit.py build/highlight-audit --top 20
```

`geometry-audit.json` содержит для каждого glyph направленные расстояния между
границами (mean/p95/max), BBox и оценку толщины, десять крупнейших связных
компонентов FN/FP и диагностические теги. Эти данные позволяют выбрать один
конкретный участок контура и проверить одну формулу за итерацию; скрипт не
изменяет исходники и не запускает оптимизацию.

Для автоматической проверки воспроизводимости добавь `--verify-repeat`:

```sh
./scripts/run-highlight-audit.sh --sizes 32,64,128 --analyze --verify-repeat
```

Инструмент повторит тот же рендер, сравнит IoU/TP/FP/FN каждого glyph и
завершится с ошибкой при любом расхождении. Повторный отчёт сохраняется в
`build/highlight-audit/_repeat/report.json`.

## Ретроспектива и правила выбора следующей правки

Матрица причин задержек и обязательные правила принятия изменений сохранены в
[`GLYPH-OPTIMIZATION-RETROSPECTIVE.md`](GLYPH-OPTIMIZATION-RETROSPECTIVE.md).
Перед новой геометрической итерацией используй полный baseline с
`--analyze --verify-repeat`, затем выбирай один glyph по крупной связной FN/FP
области. Критерий принятия остаётся строгим: общий IoU должен вырасти,
изменённый glyph не должен увеличить FN, повторный запуск должен совпасть.

Для автоматического выбора следующего кандидата без изменения исходников:

```sh
./scripts/next-glyph-plan.py --size 64 --top 12
```

Скрипт создаёт `build/highlight-audit/next-glyph-plan.json`: приоритет,
крупнейшие FN/FP, BBox, boundary p95, одну логическую группу параметров и
одну проверяемую гипотезу. Это сокращает ручное чтение atlas перед каждой
итерацией; решение о принятии всё равно выполняется полным audit ×2.

Чтобы извлечь конструктивную логику эталона из масок, а не искать исходные
Bézier-координаты:

```sh
./.venv/bin/python scripts/infer-reference-logic.py --threshold 0.50
```

`build/reference-contours/logic.json` содержит топологию (компоненты и
отверстия), ось и меру симметрии, профиль толщины, медальные landmarks из
distance transform и консервативный класс построения. Это наблюдаемая
структура растрового эталона; она не утверждает, что восстановлены оригинальные
узлы Apple.

## Аудит вариативной толщины

Контрольная точка `wght=400` не показывает дефекты крайних мастеров. Запускай
отдельный аудит:

```sh
./scripts/run-weight-highlight-audit.sh --weights 100,400,800 --sizes 64 --verify-repeat
```

`build/weight-highlight-audit/report.json` содержит отдельные IoU, FP/FN, BBox
и thickness delta для каждого glyph в каждом весе. `thickness` — медиана,
среднее и p90 диаметра локального заполненного штриха; `*-highlight.png` в
каталоге веса используют ту же карту ошибок (серый/красный/синий). Поле
`byWeight` показывает систематический уклон толщины и двадцать крупнейших
проблемных glyphs. Изменение формы или толщины допускается только после этого
измерения и отдельной проверки соответствующего веса.
