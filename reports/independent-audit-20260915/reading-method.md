# Independent role 5 — sustained screen-reading methods

Scope: independent methods review of README and fresh root fixture source, 2026-09-15. No prior audit verdicts read; no participants, human outcomes or browser-rendering results collected. This is a role-based reviewer, not a named human expert or Apple assessment.

**Conclusion:** current evidence supports inspecting rendering and reflow in the specified sample, not an empirical verdict on sustained reading. This is an evidence gap, not proof of a font defect. README's stated uses are UI, headings, short labels and numbers; do not expand that into a sustained-reading claim on the strength of this fixture.

The fixture implements font-load checking and 64 combinations of family, container width, size, CSS enlargement, spacing and theme. Its source can establish test coverage and limitations; only execution establishes the results of those checks. Bounding-box overflow checks cannot establish reading speed, comprehension, visual search accuracy, fatigue, individual accessibility or universal WCAG conformance. `overflow-wrap:anywhere` can suppress overflow while creating unattractive word breaks; absence of overflow is not a reading-quality result. Equal CSS sizes test the intended deployment, not matched perceived size. The current text mixes brief UI material and a few RU/EN paragraphs, rather than sustained passage reading.

## Prioritized findings

- **RM1 · P1 conditional on a sustained-reading release claim · confidence high:** No human evidence establishes sustained-reading suitability; current fixture explicitly disclaims it. README promises UI, headings, short labels and numerical data, not validated sustained reading. Acceptance: Keep sustained-reading status unvalidated until a preregistered human comparison is completed; publish observations and limits, not universal superiority.

- **RM2 · P2 · confidence high:** A is always Tabuna and B always system-ui; identical short bilingual content appears side by side. This is useful visual inspection but cannot produce an unbiased reading-time or comprehension comparison. Acceptance: Use sequential anonymous conditions, counterbalanced order and matched distinct passages; conceal assignment from scorer and wait for fonts before timed exposure.

- **RM3 · P2 · confidence high:** The 1x/2x fixture factor doubles CSS font size; it does not establish performance on actual 1x/2x displays, older readers, corrected vision or low vision. Acceptance: Record physical display density, OS scaling, browser zoom and devicePixelRatio separately; include age/vision variation in a pilot, with descriptive subgroup outcomes only.

- **RM4 · P3 · confidence high:** Fixture font_sha256 labels the TTF hash even though the browser loads WOFF2. The served WOFF2 matches dist WOFF2, but provenance should identify both explicitly. Acceptance: Store source_ttf_sha256 and served_woff2_sha256 separately with OS/browser/resolved system font and trial configuration.

## Executable human pilot protocol

1. **Freeze the question and artifacts.** Compare this exact Tabuna WOFF2 with the actual resolved `system-ui` on the target platform. Ask whether the deployment is promising enough for a larger reading study. Register the font hashes, browser/OS, CSS (initially 17px/1.55, weight 400, optical sizing auto), fixed pixel reading column, contrast and primary endpoints before recruiting. Equal CSS size is the primary product comparison; matched perceived-size testing would be a separate experiment.
2. **Recruit a feasible pilot.** Target 16 consenting adult RU/EN-proficient readers; this is a feasibility choice, not a power calculation. Seek eight aged 18–44 and eight aged 45+, and record age, language proficiency, habitual correction, self-reported reading difficulty and visual conditions. Include correction users and, where feasible, some low-vision users with their usual accommodations. Do not ask anyone to remove needed correction. Report recruitment gaps; a small heterogeneous sample does not validate subgroups. Use deidentified records and permit stopping without penalty.
3. **Prepare passages.** Have an independent editor prepare eight distinct neutral passages per language, each approximately 1,200–1,500 words, with comparable difficulty and unfamiliar content. Independently review eight comprehension questions per passage, including inference questions. Prepare separate short proofreading/transcription tasks containing RU/EN confusables, numbers and punctuation. Never reuse a passage for a participant or display both fonts together. Pilot timing first; if the selected passage length does not provide roughly 6–10 minutes of natural reading, revise all passage sets before main pilot collection. Do not force a minimum duration or truncate slow readers.
4. **Counterbalance and mask.** Run two sessions, one per language, with language order balanced. Each session has four sequential conditions: Tabuna/1x display, system-ui/1x, Tabuna/2x display, system-ui/2x. Assign the four balanced orders `A B D C`, `B C A D`, `C D B A`, `D A C B` equally, where A–D represent those four conditions; rotate distinct passage assignment independently across conditions. Use anonymous trial codes with no font names or preference framing. Conceal the font mapping from scorer and initial analyst. Readers may recognize shapes, so describe this as identity masking, not guaranteed blinding.
5. **Control and record screens.** Use actual 1x and 2x displays, record panel resolution, physical size/PPI, OS scaling, browser zoom, devicePixelRatio, viewing distance and lighting. Keep apparent text size and layout as comparable as feasible. Hardware changes are confounded with display density unless calibrated/matched; interpret results as these device conditions, not a causal density effect. CSS 200% enlargement and browser zoom are separate accessibility checks. Keep each reader's accommodations fixed across that reader's font pair and report them.
6. **Run each block.** Give a short unrelated practice passage, then confirm font loading before showing trial text. Time from first display until the reader selects Finished; record pauses and interruptions. Hide the passage and present the eight comprehension questions without a speed incentive. Follow with the separately timed proofreading/transcription task; count omissions, substitutions and false corrections separately. Ask visual fatigue/effort on anchored 0–10 scales immediately before and after each reading block; record symptoms and preference separately. Give at least a three-minute break and extend until the reader feels ready. Plan about 45–60 minutes per language session, longer with accommodations; stop for discomfort.
7. **Analyze descriptively.** Report completion and adverse symptoms first, then paired font differences in reading time/words per minute, comprehension proportion, transcription/error rate and fatigue change. Show individual results and uncertainty; separate RU/EN and device conditions. Never equate faster reading with better reading when comprehension falls. Specify exclusions (technical load failure, interruption) in advance, retain reasons and do not exclude slow readers merely for being slow. Use participant-level paired summaries; trials from the same person are not independent participants.
8. **Preregister a product decision.** Candidate gates for proceeding to a larger study: no unresolved reproducible truncation/fallback or disabling confusion; median within-reader Tabuna time ratio no greater than 1.05; comprehension difference no worse than −5 percentage points; added errors no greater than 1 per 100 scored opportunities; median excess fatigue change no greater than 1 point on the 0–10 scale. These numbers are proposed product tolerances, NOT research norms, established accessibility thresholds or evidence of non-inferiority. Review individual harms and any language/device pattern even if pooled gates pass. A pilot missing a gate calls for investigation or redesign; passing only supports continuing evaluation.

## Pilot versus a powered non-inferiority study

The pilot tests feasibility, instrumentation, passage balance, tolerability and approximate variability. It cannot confirm universal readability, prove equality, or establish non-inferiority through a nonsignificant test. For a confirmatory study, choose one primary endpoint and justify its non-inferiority margin in advance; preregister a comprehension safeguard, fatigue/error rules, estimand, missing-data rules, multiplicity and language/device scope. Calculate sample size using defensible paired variance and desired power/alpha, allowing uncertainty in pilot estimates and attrition. Use counterbalancing and an analysis that handles participant and passage effects. A non-inferiority conclusion requires the specified confidence bound to stay inside the prespecified margin; descriptive pilot medians do not meet that requirement.
