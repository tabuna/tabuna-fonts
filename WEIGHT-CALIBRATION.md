# Соответствие нативного эталона весам CSS

Проверено 2026-09-11: macOS 26.5.2 (25F84), Chromium 152.
Числа ниже относятся к сборке 0.680. В 0.690 перекалиброваны также
семь прямолинейных контролей; актуальные итоги — в [REVIEW.md](REVIEW.md).
Сборка 0.680 исправляет выбор крайних весов эталона и перекалибровывает
28 собственных букв. Цель полного совпадения всей гарнитуры не достигнута.

## Причина расхождения

Прежний нативный инструмент сопоставлял CSS 100 с `NSFont.Weight.ultraLight`,
а CSS 900 — с `.black`. Публичные параметры выбранного системного шрифта
показали другую координату `wght`: приблизительно 30.925 и 1000 соответственно.
Поэтому прежняя калибровка крайних весов использовала другой эталон.

`scripts/measure-reference-weights.swift` сравнивает именованный выбор
с явным запросом `wght` и `opsz` через CoreText. Измеряются только ширины,
растровые границы и публичные параметры выбора; контуры и таблицы эталона
не извлекаются. `weight-calibration.html` независимо измеряет настоящий
`system-ui` в Worker Chromium.

18 букв × 4 размера (16/32/64/128) × 9 весов (100–900):

| Выбор нативного эталона | Ширины, совпавшие с Chromium |
| --- | ---: |
| Именованное начертание AppKit | 146 из 648 |
| Явная ось wght, opsz = размер | 648 из 648 |

Это сравнение ширин системных эталонов, не проверка 648 собственных глифов.
Для сопоставления применено округление нативной ширины к целому значению
в 2048 UPM: `round(advance * unitsPerEm / size) * size / unitsPerEm`.
Полученное значение сравнивается с фактически измеренной шириной браузера.
Например, у системной I, 100/64, CoreText даёт 10.50533676147461,
а браузер — 10.5; у I, 900/64 — 18.864479064941406 и 18.875.
Нулевой остаток всех 648 проверок подтверждает этот способ предсказания
ширины в проверенном окружении. Он не доказывает равенство растров или
такое же поведение всех браузеров.

Данные: [выбор шрифтов](proofs/reference-weight-selection.json),
[браузерная проверка выбора](proofs/css-reference-validation.json).
Диагностический браузерный запуск использовал собственный файл 0.670;
его хеш сохранён отдельно от последующих результатов сборки 0.680.

## Что изменилось в 0.680

`render-pairs.swift` и `measure-text.swift` теперь по умолчанию запрашивают
оси явно. Режим `named` сохранён для воспроизведения исторических измерений.
В JSON записывается `referenceWeightMode`; новые калибраторы требуют `axis`.

Повторно подобраны параметры пяти собственных конструкций:
ПпШшЦцЩщТтНн, ЬьЪъЫы, PРD, BВв, oOоО. Число и устройство сегментов
задаются нашими модулями, из эталонных растров подбираются скалярные размеры
и длины касательных. Повторно измерены 32041 пара и 360 строк с двоеточием
в шести положениях осей; число ненулевых пар осталось 6585.
Исходные параметры Regular, его кернинг и контекстное двоеточие не изменились.

После изменения крайних мастеров совместимое преобразование кубических
кривых в TrueType может изменить точки Regular. Его растры проверены
отдельно: 9 улучшений, 80 неизменных, 23 ухудшения из 112.
Средний ink IoU немного снизился с 99.7032% до 99.6823%; например,
у ь на 16 pt снижение составляет 0.006698 по шкале 0–1.
Сохранение исходных параметров не означает отсутствия растровой регрессии.

## Готовый файл в браузере

Независимый Worker проверяет 35 букв, три веса и четыре размера.
Хеш загруженного WOFF2 совпадает с файлом сборки.

| CSS-вес | Точные ширины | Пиксели вместе с шириной |
| --- | ---: | ---: |
| 100 | 112 из 140 | 6 из 140 |
| 400 | 140 из 140 | 54 из 140 |
| 900 | 112 из 140 | 7 из 140 |

У всех 28 перекалиброванных букв совпали все 336 ширин; полное совпадение
растров вместе с шириной — 45 из этих 336. Оставшиеся семь контрольных букв
I/H/E/F/L/Е/І дают ошибки ширины на крайних весах и требуют собственной
калибровки. Самопроверка повторного системного рендера: ноль отличий.

DOM Regular: 389 точных ширин из 468; промежуточные размеры 18/20/24 px
остаются неточными. Все 468 ширин WOFF2 совпадают с TTF после OTS.
Смешанный Canvas/DOM: 25 точных растров и 1 полное совпадение из 72.
Его зависимость от истории DOM сохраняется как отдельная проблема
([описание](CANVAS-CALIBRATION.md)).

Агрегаты реального браузерного запуска:
[web-layout-0.680.json](proofs/web-layout-0.680.json).

## Нативный результат и пределы проверки

До и после отрисованы против одного и того же нового эталона `axis`;
все соответствующие системные PNG побитно одинаковы. Набор:
28 букв × 3 веса × 4 размера, обычная сетка 2×.

| Вес | Средний ink IoU до → после | Точные растры | Точные нативные ширины |
| --- | ---: | ---: | ---: |
| 100 | 67.6130% → 98.9592% | 8 из 112 | 0 из 112 |
| 400 | 99.7032% → 99.6823% | 36 из 112 | 112 из 112 |
| 900 | 91.1472% → 99.7454% | 8 из 112 | 0 из 112 |

Все 224 крайних сравнения улучшились. Всего: 233 улучшения, 80 неизменных,
23 ухудшения. Ink IoU — диагностическая мера только этого набора,
не процент готовности шрифта. Нативные дробные метрики не округляются
для объявления успеха: на крайних весах точных нативных ширин нет.
Браузерный успех ширин получен отдельным реальным измерением.

Строгая проверка 14 строк × 4 размера сохраняет FAIL: Regular 56/56,
веса 100/900 — по 0/56. Остальные буквы, промежуточные веса, оптическая
интерполяция, формирование строк и пиксели всей гарнитуры остаются в работе.
Технические проверки: 38 PASS; FontBakery 101 PASS, 0 FAIL, 2 WARN,
3 INFO, 21 SKIP; OTS принимает файл. Они не заменяют проверку рисунка.
