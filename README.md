# Tabuna Sans

Собственный вариативный шрифт, созданный с нуля для веба. Исходники содержат
авторские координаты контуров, метрики и пятнадцать мастеров. Готовые гарнитуры
и контуры Apple/Microsoft не используются. Системный Apple — эталон точного сравнения.

**Статус: версия 0.900, рисунок проходит доводку.** Это работающая гарнитура,
но равенство качеству системных шрифтов Apple/Microsoft не заявляется.
Первоначальная геометрическая версия переработана после визуальной проверки:
у основных букв и цифр внешние контуры и просветы проектируются отдельно.

Inter изучается как технический пример для ускорения собственного старта:
[результаты сравнения и границы использования](INTER-EVALUATION.md).
Готовые контуры Inter не переносятся в Tabuna Sans. Допустимо подсмотреть код,
устройство параметров, мастеров и сборки. Цель — 100% совпадения с зафиксированным
системным Apple, включая пиксели и поведение текста; сейчас она не достигнута.

## Посмотреть

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

Можно также открыть `index.html` напрямую: каталог символов и фильтры работают
без HTTP-сервера. `sources/charset.js` генерируется вместе с `charset.json` при сборке.

Откройте [локальный стенд](http://127.0.0.1:4173). Он позволяет менять текст,
толщину, размер и оптический размер; сравнение использует системный шрифт
вашего устройства. Элементы управления используют системный стек Algo UI,
а образцы явно подключают Tabuna Sans. На узком экране образец переносится.

Отдельный [режим сравнения по пикселям](http://127.0.0.1:4173/comparison.html)
показывает два PNG одного символа — Tabuna и системный Apple — и цветную разницу.
Размеры 16/32/64/128 pt, вес Regular 400, нативное сглаживание в одинаковом
CoreText-контексте. Можно скачать каждое изображение и увидеть точное число
различающихся пикселей. Точного совпадения текущая версия не достигла.

## Подключение

Файлы для самостоятельного размещения находятся в `dist/`:

- `TabunaSansVariable.woff2` — веб-шрифт, все символы и обе оси в одном файле.
- `TabunaSansVariable.ttf` — вариативный TrueType для совместимых приложений.
- `tabuna.css` — `@font-face` и класс `.tabuna`, без глобальной замены шрифта.
- `manifest.json` — версия, диапазоны осей и размеры готовых файлов.

```html
<link rel="stylesheet" href="dist/tabuna.css">
<p class="tabuna">Ясность в каждой букве.</p>
```

```css
.tabuna {
  font-weight: 450;
  font-optical-sizing: auto;
}
.tabuna.manual-optical {
  font-optical-sizing: none;
  font-variation-settings: "opsz" 24;
}
.tabuna.numbers { font-variant-numeric: tabular-nums; }
```

Оси: `wght` 100–900 (по умолчанию 400), `opsz` 9–128 типографских пункта
(по умолчанию 14). `font-weight` продолжает работать при ручном `opsz`.
Для обычного текста рекомендуется автоматическая оптика. Синтетический
курсив не является авторским курсивным начертанием.

## Покрытие

Латиница, Latin-1 и Latin Extended-A; кириллица U+0400–045F и Ґ/ґ;
Ș/ș/Ț/ț; пунктуация, валюты, основные математические знаки и 14 комбинируемых
диакритик. Точный обязательный набор хранится в `sources/charset.json`.
OpenType: кернинг латиницы и кириллицы, `mark`/`mkmk`, `liga`, `calt`, `tnum`/`pnum`,
позиции курсора внутри лигатур. Стиль — прямой; курсив и таблица MATH не входят
в эту версию. Остальные письменности обслуживаются системным запасным шрифтом.

## Состав репозитория

В Git хранятся код в `scripts/`, параметры и наборы символов в `sources/`,
HTML-стенд, документация, лицензия и готовые файлы шрифта в `dist/`.
UFO-мастера и Designspace создаются командой сборки и не коммитятся.

`build/`, `references/`, `proofs/`, локальное Python-окружение и кэши исключены
через `.gitignore`. Ссылки на измерения и изображения в отчётах относятся
к локальным результатам: они не входят в этот репозиторий. Для повторения
калибровок нужны соответствующие эталонные измерения; обычная сборка использует
сохранённые параметры из `sources/`.

## Воспроизводимая сборка

Нужен Python 3.10+ и зависимости из `requirements.lock`; текущее окружение
проверено на Python 3.14/macOS. Зависимости устанавливаются отдельно от шрифта.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python scripts/build.py
```

Первая стадия генерирует UFO-мастера и Designspace из авторских параметрических
исходников. Вторая компилирует их через fontmake и FontTools, затем упаковывает
WOFF2. Сборка не читает файлы каких-либо других шрифтов. Сетевых запросов при
сборке нет. Временные файлы находятся в `build/`; в `dist/` попадают законченные
файлы. Временная метка сборки фиксирована.

```sh
# Только исходники:
.venv/bin/python scripts/build.py --sources-only
# Только компиляция, чтобы сохранить ручные изменения в UFO:
.venv/bin/python scripts/build.py --compile-only
```

Параметрический рисунок находится в `scripts/refined.py`, `scripts/design.py`
и `scripts/symbols.py`; геометрические операции — в `scripts/geometry.py`.
UFO можно открыть в совместимом шрифтовом редакторе. Полная генерация
перезаписывает UFO: постоянные изменения следует перенести в параметрические
исходники либо работать через `--compile-only`.

## Автоматическая калибровка системного эталона

Техническое изучение Inter используется для ускорения собственной реализации.
Конечная цель — нулевые различия с системным Apple, а не максимальный процент
сходства. Текущий эталон зафиксирован в JSON вместе с версией macOS.

После первоначальной сборки можно пересчитать оптическую зависимость и трекинг:

```sh
.venv/bin/python scripts/fit-optical-map.py
.venv/bin/python scripts/calibrate-tracking.py
.venv/bin/python scripts/build.py --compile-only
```

Поиск работает через отрисовку собственной `I` и системного эталона.
`sources/optical-map.json` хранит найденные значения оси в точности F2Dot14;
`sources/tracking.json` — измеренные поправки ширины. Они входят в сборку.
Поправки записываются в служебные точки OpenType `gvar`; таблица `HVAR`
сохраняется только в контрольном файле сборки. Ошибки округления сохраняются
отдельно и не считаются точным совпадением. После изменения базовой ширины `I`
эти измерения нужно повторить. Успех калибровочной буквы не означает готовности
всей гарнитуры.

Версия 0.5 добавляет измеренные пропорции 244 исходных знаков:
`scripts/metrics.py` меняет собственные контрольные точки, сохраняя топологию
контуров. Боковые поля и ширины индивидуальны; строчная, верхние и нижние
выносные элементы корректируются раздельно. `sources/metrics.json` содержит
числовые параметры, а не контуры эталона. Их можно воспроизвести командой
`.venv/bin/python scripts/calibrate-metrics.py` из сохранённой собственной
базы `references/metrics-baseline/`. Измерения относятся к Regular; остальные
веса сохраняют собственную вариативность и ещё требуют сверки с эталоном.

В версии 0.4 AAT `trak` заменена на OpenType `HVAR`: поправки переживают OTS
и действуют в проверенном Chromium. Ось расширена до 128; 15 мастеров
сохраняют отдельные координаты для размеров с одинаковой формой и разными
интервалами. Браузерная проверка — `web-calibration.html`; текущие данные —
`proofs/web-portable-tracking.json`. Совпадение ширины не доказывает совпадение
пикселей. Предыдущий неудачный эксперимент сохранён в `proofs/web-tracking.json`
и `proofs/portable-tracking-analysis.json`.

Поправки также записываются в служебные точки `gvar`, чтобы преобразование
вариативного TTF в статическое начертание сохраняло те же ширины, что HVAR.
Стенд отдельно сравнивает Canvas и HTML: их результаты не взаимозаменяемы.

В сборке сохраняется направление авторских контуров (`--keep-direction`):
их повторный разворот приводил к различию сглаживания даже прямоугольника.
`comparison.json` различает равенство пикселей (`exactMatch`) и равенство
пикселей вместе с шириной, без запасного шрифта (`completeMatch`).

Отключена оптимизация IUP при сборке `gvar`: её допуск 0.5 единицы шрифта
менял заданную геометрию даже в положениях мастеров. Параметр
`--no-optimize-gvar` сохраняет координаты; упаковка WOFF2 остаётся без потерь.
Проверка сопоставляет вершины 12 прямолинейных глифов из UFO с координатами
вариативного TTF в девяти положениях осей.

Нативный набор содержит 144 сравнения: 12 букв × 3 веса × 4 размера.
Отдельно учитываются совпадение пикселей и ширины. В UltraLight остаются
дробные расхождения метрик; полное совпадение гарнитуры не достигнуто.
Данные: `proofs/rectilinear/results.json`; сравнение до/после:
`proofs/rectilinear/progress.png`.

## Доводка плеч и просветов в 0.620

Уточнены `n/h/m` в Regular: толщины стоек, высоты просветов и форма плеч.
Каждое плечо построено из двух внешних и двух внутренних кубических сегментов.
Для совместимости мастеров прежние кубические дуги крайних весов разделены
точным алгоритмом де Кастельжо. Их исходная геометрия при этом сохраняется.

Подбор скалярных параметров по нативному рендеру воспроизводится через
`scripts/calibrate-shoulders.py`; параметры хранятся в `sources/shoulders.json`,
а применяет их `scripts/shoulders.py`. Полного попиксельного совпадения нет.
Проверка на обычной сетке: `proofs/shoulders/results.json`; сравнение до/после:
`proofs/shoulders/progress.png`. Пересоздание сводки из готовых рендеров:
`.venv/bin/python scripts/proof-shoulders.py`.

## Доводка круглых форм в 0.610

Уточнены собственные кривые и просветы `o/O/о/О` в Regular. Параметры четырёх
кубических сегментов получены из увеличенных нативных рендеров при сохранённом
оптическом размере. Готовые контуры системного шрифта не извлекаются.
Измерения и воспроизводимый подбор: `references/rounds-baseline/`,
`scripts/calibrate-rounds.py`, `sources/rounds.json`.

На обычной сетке 2× все 16 сравнений улучшились; полного совпадения пикселей
пока нет. Сводка и изображения: `proofs/rounds/results.json`,
`proofs/rounds/progress.png`. Пересоздание сводки из готовых рендеров:
`.venv/bin/python scripts/proof-rounds.py`.

## Проверка

Версия 0.6 использует измеренный кернинг: 32 041 пара в шести точках
(веса 100/400/900, размеры 16/64). Ненулевые значения 6585 пар хранятся
в `sources/kerning.json`. Латинские и кириллические группы разделены;
дробные измерения сохраняются до округления при сборке.

`colon.case` выбирается контекстным `calt` между подтверждёнными прописными
буквами и цифрами. Этот вариант составлен из собственного двоеточия,
с измеренными положением и кернингом. Параметры — `sources/colon-context.json`.
Лигатуры сохраняют интервалы составляющих букв, включая размерный трекинг.

Для повторных измерений строк на macOS:

```sh
swiftc scripts/measure-text.swift -o build/measure-text
.venv/bin/python scripts/calibrate-kerning.py
.venv/bin/python scripts/calibrate-colon.py
.venv/bin/python scripts/verify-text.py
```

Калибровочные команды используют сохранённые результаты системного рендерера
из `references/css-weights-baseline/kerning/` и
`references/css-weights-baseline/colon-context/`. Прежние базы сохранены
для исторического именованного выбора эталона.
`verify-text.py` измеряет реальные строки заново. Проверка точного совпадения
пока завершается ошибкой: ширины Thin и Black не доведены до эталона.

```sh
.venv/bin/python scripts/verify.py
.venv/bin/python scripts/verify-rectangle.py
.venv/bin/python scripts/proof.py
.venv/bin/fontbakery check-universal dist/TabunaSansVariable.ttf \
  --skip-network --json proofs/fontbakery.json
node --check demo.js
```

Проверяются реальные бинарные файлы: покрытие Unicode, формирование текста
HarfBuzz, кернинг, диакритика, табличные цифры, оптическая ось, 72 проверяемых
положений осей, отсутствие обрезания и сохранность просветов в основных буквах.
`proofs/` содержит отчёты и изображения, нарисованные из готового TTF через
FreeType. Эти проверки дополняют визуальную оценку, а не заменяют её.

Проверки в браузере и оставшиеся ограничения описаны в `REVIEW.md`.

### Пересоздать попиксельные сравнения (macOS)

```sh
mkdir -p build
swiftc scripts/render-pairs.swift -o build/render-pairs
for size in 16 32 64 128; do
  build/render-pairs dist/TabunaSansVariable.ttf "proofs/pixel-$size" "$size"
  .venv/bin/python scripts/compare-pixels.py "proofs/pixel-$size"
done
```

После размера `render-pairs` принимает набор символов, например `'аеонДЛЖ'`,
затем необязательные масштаб, вес и режим эталона `axis|named`.
По умолчанию: масштаб 2, вес 400 и явные оси `axis`;
`named` сохраняет исторический способ выбора.
Набор по умолчанию содержит 98 разных символов. CoreText отрисовывает
системный шрифт, не извлекая его контуры или шрифтовой файл. Собственный TTF
открывается напрямую, без установки в систему. `comparison.json` содержит
SHA-256 проверенного TTF, версию macOS, параметры осей и реальные имена
отрисованных шрифтов; запасная гарнитура отмечается отдельно.

Протокол проверяет сам себя: дважды рисует один и тот же системный символ
и требует нулевой разницы. `exactMatch` означает равенство всех пикселей.
`inkIoU` — взвешенное пересечение чернил, без учёта пустого белого фона.
Изображения не растягиваются и не сдвигаются для улучшения оценки.

Для связного текста используйте `@sources/text-proof.json` вместо набора
символов. В этом режиме стандартный кернинг включён; режим отдельных
символов сохраняет прежние условия проверки.

Для другого веса укажите масштаб и вес после набора символов, например:
`build/render-pairs dist/TabunaSansVariable.ttf proofs/black 16 ПпШшЦцЩщТтНн 2 900`.
Явный масштаб 2 сохраняет обычную сетку и размеры холста; увеличение масштаба
используется только для подбора параметров при неизменном оптическом размере.

## Рисунок Ф/ф в 0.900

В исходной кириллической конструкции `scripts/design.py` добавлена оптическая компенсация кольца Ф/ф по оси `wght`: в Thin кольцо сохраняет системную читаемую толщину, в Black поправка мягче. Поправка применяется до общих метрик и не меняет advance width. Проверка на 64 px: Regular IoU Ф/ф `0.814534 / 0.552026`, Thin `0.691929 / 0.298966`, Black `0.865060 / 0.710222`; крайние веса требуют дальнейшей доводки нижнего ф.

Дополнительно в 0.900 вертикальный размер кольца нижнего `ф` расширен независимо от заглавного `Ф`; это уменьшает системное расхождение контрформы на Thin, Regular и Black без изменения advance width.

## Рисунок 5 в 0.900

В refined-контуре цифры 5 верхняя полка получила весозависимое укорочение: в Regular и Black она ближе к системной форме, а в Thin сохраняется исходная длина. Advance width не изменён.

### Контрольная метрика текущей сборки

Полный контрольный набор из 126 glyphs (кириллица, латиница и цифры) сравнен с системным SF через CoreText на 32, 64 и 128 px. Средний inkIoU составляет `0.889925`; по размерам: `0.889408 / 0.889889 / 0.890477`. Тест не заменяет визуальную проверку и фиксирует текущее состояние для последующих итераций.
